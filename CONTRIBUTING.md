# Contributing

Thanks for your interest in contributing! 🎉

Whether you're fixing a bug, improving documentation, adding a feature, or just making a small cleanup, every contribution is welcome.

## Getting Started

### 1. Fork the repository

Create your own fork of this repository on GitHub.

### 2. Clone your fork

```bash
git clone https://github.com/emsar69/Bliss
cd Bliss
```

### 3. Create a branch

Create a new branch for your changes. Please avoid working directly on `main`.

```bash
git checkout -b feature/my-feature
```

Use a descriptive branch name, for example:

```text
feature/add-search
fix/login-error
docs/update-readme
refactor/api-client
```

### 4. Make your changes

Make your changes while keeping the existing project structure and conventions in mind.

Please keep changes focused. Smaller, well-defined pull requests are generally easier to review and merge.

## Code Style

Please follow the existing code style and conventions used throughout the project.

Before submitting your changes:

* Keep formatting consistent with the surrounding code.
* Use clear and descriptive names.
* Avoid unnecessary complexity.
* Keep functions and modules focused.
* Remove unused code, imports, and debugging statements.
* Run the project's formatter or linter when available.

If the project already has automated formatting or linting configured, please use those tools rather than manually formatting code.

## Commit Messages

Keep commit messages clear and descriptive.

For example:

```text
Add search filtering
Fix authentication redirect
Update installation instructions
```

Try to keep each commit focused on a single change.

## Opening a Pull Request

When your changes are ready:

1. Push your branch to your fork:

```bash
git push origin feature/my-feature
```

2. Open a Pull Request against this repository's `main` branch.

3. In the PR description, explain:

   * What you changed
   * Why you made the change
   * How you tested it
   * Any relevant issues or additional context

A useful PR description might look like:

```markdown
## What changed

Added filtering to the search results.

## Why

Users needed a way to narrow results by category.

## Testing

- Added unit tests for category filtering
- Ran the full test suite
```

## Pull Request Guidelines

Before submitting your PR, please make sure:

* Your changes are focused and easy to review.
* Compiles/Runs locally.
* New or changed behavior is covered by tests where appropriate.
* Code follows the project's existing style.
* The PR description clearly explains the change.
* You have rebased or updated your branch if needed.

Maintainers may suggest changes during review. Don't take review comments personally, we're all here to make the project better. 💙

## Issues

Found a bug or have an idea?

Feel free to open an issue and provide as much useful information as possible.

For bug reports, include:

* What happened
* What you expected to happen
* Steps to reproduce the issue
* Relevant logs or error messages
* Your environment, when relevant

For feature requests, explain the problem you're trying to solve and why the proposed feature would be useful.

## Be Respectful

We're building this project together. Please be respectful, constructive, and welcoming to other contributors.

Different perspectives and experience levels are valuable, and questions are always welcome.

## Thank You!

Thanks for taking the time to contribute! Every improvement helps make the project better. 🚀
